# JIU 邮箱密码登录设计

## 目标

在现有 Cloudflare Workers + D1 会话体系上增加邮箱密码注册和登录，同时保留游客模式。第一版不发送邮件、不做邮箱验证、不做找回密码。

## 用户体验

- 新增 `/login` 页面，使用现有 JIU 的奶油色、橙色、深蓝色和圆角卡片风格。
- 登录态：邮箱、密码、登录按钮、注册入口、游客模式入口。
- 注册态：邮箱、昵称、密码、确认密码、注册按钮。
- 支持密码显示/隐藏、字段级错误、提交中状态和成功后的回跳。
- 登录页面不显示底部导航和陪伴小鸟，避免干扰表单。
- 个人中心增加登录/注册入口；游客仍可继续使用应用。

## 认证与数据

- D1 `users` 增加 `password_hash` 和 `password_salt` 字段，并为邮箱建立唯一索引。
- 邮箱统一 trim + lowercase 后保存和查询。
- 密码使用 Worker Web Crypto 的 PBKDF2 派生哈希保存，不保存明文密码。
- 登录成功后复用现有签名 HttpOnly `jiu_session` Cookie。
- 登录接口不返回密码哈希或 salt。
- 登录失败统一返回“邮箱或密码不正确”，避免暴露账号是否存在。

## 游客升级

- 注册接口允许带当前游客 session。
- 如果当前会话对应游客账号，注册成功后将该用户升级为邮箱用户，保留其作品、帖子、收藏、点赞、评论等关联数据。
- 如果游客没有会话，则创建新的邮箱用户。
- 已注册邮箱不能重复使用；游客升级遇到重复邮箱时提示先登录已有账号，不自动合并两个账号。
- 退出登录只撤销当前 session，不删除用户数据。

## API

- `POST /api/auth/register`：创建邮箱账号或升级当前游客账号。
- `POST /api/auth/login`：校验邮箱密码并创建 session。
- `POST /api/auth/logout`：沿用现有退出接口。
- `GET /api/me`：沿用现有用户信息接口，返回登录用户类型、邮箱、昵称和头像。
- `POST /api/auth/guest`：沿用现有游客登录入口。

## 校验与安全

- 邮箱格式校验，长度限制 254 字符。
- 密码长度限制 8-72 字符，注册时两次密码必须一致。
- 昵称长度限制沿用个人资料规则。
- 使用随机 salt；PBKDF2 使用 SHA-256 和足够迭代次数。
- 对登录接口增加轻量失败节流，避免明显的暴力尝试。
- 不在前端 localStorage 保存密码；本地状态仅作为游客离线兜底和界面镜像。

## 验收标准

1. 游客可以正常使用现有功能。
2. 游客注册邮箱账号后，原有作品和社区内容仍归属于新邮箱账号。
3. 新账号可退出并重新登录，刷新页面后身份保持。
4. 重复邮箱、错误密码、弱密码、密码不一致均有明确提示。
5. 类型检查、Lint、现有测试和新增认证测试全部通过。
6. Cloudflare 本地 D1 和远程 D1 migration 均可执行。

## 不在本次范围

- 邮箱验证码和邮件发送。
- 忘记密码/重置密码。
- 第三方 OAuth。
- 管理员账号和多设备会话管理。
