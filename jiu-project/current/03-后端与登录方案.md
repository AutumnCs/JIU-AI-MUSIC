# 后端与登录方案

> 当前版本：Cloudflare 主线版
> 基准日期：2026-08-04

> 说明：阿里云体系已移到归档文档 `[阿里云后端体系.md](../archive/阿里云后端体系.md)`，这里只保留当前主线。

## 1. 目标

先把 Jiu 的“游客模式”跑通，形成一套最小但完整的账号体系：

- 用户第一次进入时自动获得稳定身份
- 作品、进度、收藏等数据可以挂到这个身份上
- 现有前端的本地状态不需要推倒重来
- 后续可以平滑升级到邮箱登录，而不是重做一套账户系统

## 2. 现状判断

当前项目已经有一层本地与服务端并存的游客态：

- `jiu-app/stores/globalStore.ts` 里仍保留本地状态
- `jiu-app/lib/server/auth.ts` 负责游客创建、当前用户查询和退出
- `jiu-app/lib/server/db.ts` 负责 PostgreSQL 兼容存储
- `jiu-app/app/layout.tsx` 负责初始化和 onboarding
- Cloudflare Workers 线上已经可访问

这说明现在的核心问题不是“有没有后端”，而是：

- 账号要先统一成服务端会话
- 前端草稿继续保留本地体验
- 后续一旦接邮箱登录，当前游客态需要有升级路径

所以这一版不做完整认证系统，只做“游客身份 + 会话 + 数据归属”的最小闭环。

## 3. 现在已经完成的部分

- 游客创建 API 已上线
- 当前用户查询 API 已上线
- 退出登录 API 已上线
- PostgreSQL 兼容存储已接到 Hyperdrive / Neon
- 公网部署已跑通

## 4. 还没做完的部分

- 邮箱登录
- 作品云同步
- 用户资料编辑
- 更完整的发布和分享
- workshop 真正的数据库后端

## 5. 设计原则

- 先让用户能用，再让用户登录
- 先做游客身份，再做正式账号
- 先保留本地状态，再逐步迁移到云端
- 接口要足够薄，避免一开始就把后端做重
- 账号体系要可升级，游客身份以后能并入邮箱账号

## 6. 当前推荐方案

### Cloudflare Workers + Hyperdrive + Neon

优点：

- 成本低
- 最适合当前“先快跑起来”的目标
- PostgreSQL 关系模型和后续扩展都比较自然
- 已经和现有代码对齐

缺点：

- 需要接 Cloudflare 的部署链路
- 比纯前端稍复杂

### 结论

采用 **Cloudflare Workers + Hyperdrive + Neon**。

## 7. 最小接口

### `POST /api/auth/guest`

创建或恢复游客身份。

返回：

- `user`
- `session`

### `GET /api/me`

查询当前身份。

返回：

- 当前用户信息
- 当前会话状态

### `POST /api/auth/logout`

退出当前会话。

说明：

- 只清理服务端 session
- 前端本地缓存可选择保留或清空

## 8. 数据结构

### `users`

- `id`
- `type`：`guest` 或 `email`
- `created_at`
- `updated_at`

可选扩展字段：

- `display_name`
- `avatar`
- `email`

### `sessions`

- `id`
- `user_id`
- `expires_at`
- `created_at`
- `revoked_at`

## 9. 数据流

### 首次进入

1. 前端启动
2. 检查本地是否已有 session
3. 如果没有，调用 `POST /api/auth/guest`
4. 后端创建游客用户和 session
5. 前端保存本地身份
6. 页面继续正常使用

### 再次进入

1. 前端读取本地 session
2. 调用 `GET /api/me`
3. 后端确认 session 有效
4. 前端恢复当前身份和用户状态

### 后续升级到邮箱登录

1. 游客点击邮箱登录
2. 创建或绑定邮箱账号
3. 迁移游客数据到新账号
4. 保留原有作品、进度和收藏

## 10. 与现有代码的关系

### `jiu-app/stores/globalStore.ts`

这里仍然是当前最关键的接入点。

建议：

- 保留现有本地存储逻辑
- 把 `jiu_user_id` 视为“当前游客身份标识”
- 后续再把 `authState` 作为独立层接入

### `jiu-app/app/layout.tsx`

这里继续负责初始化：

- 初始化游客身份
- 控制 onboarding
- 渲染全局导航和陪伴组件

### `jiu-app/app/workshop/page.tsx`

后续可以把作品保存从纯本地扩展到服务端。

### `jiu-app/app/community/page.tsx`

后续可以把“我的作品”和“社区作品”统一到云端数据来源。

## 11. 验收标准

满足以下条件，就算游客模式和基础后端跑通：

- 用户首次打开应用会自动获得身份
- 关闭页面后再打开，身份仍可恢复
- 作品和进度能绑定到同一身份
- 当前前端功能不被破坏
- 后续可以在不重做前端的情况下接入邮箱登录
