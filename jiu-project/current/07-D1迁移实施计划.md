# D1 Migration and Provider Abstraction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the runtime Hyperdrive/Neon persistence layer with Cloudflare D1 without losing auth, music ownership, or community features, then route music and lyric generation through explicit providers.

**Architecture:** Next.js API routes keep their public paths and delegate to focused Auth, MusicTask, and Community repositories backed by the `DB` D1 binding. Volcengine and Ark details move behind server-side provider interfaces; R2 remains the permanent audio store through the single `MUSIC_BUCKET` binding.

**Tech Stack:** Next.js App Router, OpenNext Cloudflare Workers, Cloudflare D1, Cloudflare R2, TypeScript, Vitest 4 Workers integration, Node test runner, Wrangler 4.

## Global Constraints

- D1 is the only runtime business database; no Neon data import is performed.
- Do not delete the existing Neon database or Hyperdrive configuration.
- Preserve Worker name `jiu-bird-collection` and all existing public API paths.
- D1 binding is `DB`, database name is `jiu-music-db`, and migrations live in `jiu-app/migrations`.
- R2 binding is only `MUSIC_BUCKET`; remove the duplicate `jiu_music_audio` binding.
- All music creation, status, audio, lyric, community write, and notification APIs require a valid signed Session.
- Production may never silently select the Mock music provider.
- Keep secrets out of source and `wrangler.jsonc`.
- Every production behavior starts with a failing test and finishes with a passing focused test.
- Do not stage or commit `docs/`, `jiu-app/.agents/`, or `jiu-app/skills-lock.json`.
