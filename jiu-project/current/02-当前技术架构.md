# Jiu 当前技术架构

> 基准日期：2026-08-03

## 1. 架构目标

当前架构的目标不是“一次性做完完整账号系统”，而是先把下面这条最小链路跑通：

- 游客进入
- 服务端创建身份和会话
- 前端继续保留草稿和临时状态
- 未来可以无缝升级到邮箱登录

## 2. 现在的分层

### 前端层

- Next.js App Router
- React 19
- Zustand 管理全局状态
- `localStorage` 继续保存草稿、临时 UI 状态和学院进度

### 服务端层

- 以 route handlers 提供最小 API
- 现在已有：
  - `POST /api/auth/guest`
  - `GET /api/me`
  - `POST /api/auth/logout`
- 服务端负责 session 校验和用户归属

### 存储层

- `DATABASE_URL` 指向 PostgreSQL 兼容数据库
- Cloudflare 线上通过 Hyperdrive 连接 Neon
- 当前实现使用 `users` 和 `sessions` 两张表

## 3. 当前部署方向

当前文档的推荐部署方向是：

- Cloudflare Workers
- Hyperdrive
- Neon Free Postgres

这条线的好处是：

- 成本低
- 体验快
- 账号、会话、用户资产都能放进同一套关系型存储
- 后面加作品、收藏、进度表会很自然

## 4. 环境变量

必需：

- `DATABASE_URL`
- `AUTH_COOKIE_SECRET`

其中：

- 本地开发可把 `DATABASE_URL` 指向 Neon 的连接串
- Cloudflare 线上则通过 Hyperdrive 代理到 Neon

## 5. 现在和未来的边界

### 现在已经有的

- 游客身份
- 会话 cookie
- 当前用户查询
- 退出登录
- PostgreSQL 兼容存储

### 现在还没做完的

- 邮箱登录
- 作品云同步
- 用户资料编辑
- 更完整的发布和分享

### 未来可升级点

- `users.type` 已经预留 `guest` 和 `email`
- 当前账号体系可以直接沿着同一张用户表扩展
- 游客数据以后可以并入正式邮箱账号

## 6. 关键实现原则

- 游客优先
- 前端本地草稿不被后端打断
- 服务端只承担身份、会话和归属
- 开发态和生产态严格分开

## 7. 你接下来要配什么

1. Neon 数据库
2. Cloudflare Hyperdrive
3. Workers 部署
4. `DATABASE_URL`
5. `AUTH_COOKIE_SECRET`
