# 「啾」核心模块细化与 MVP 范围定义

> 日期：2026-07-29 | 版本：v1.0 | 状态：待审阅

---

## 〇、减法原则（先说清楚不做什么）

### 明确砍掉的功能

| 原计划 | 砍掉理由 | 替代方案 |
|--------|---------|---------|
| 完整 9 关课程 | 时间不够 | 只做 3 关（每阶段 1 关代表） |
| 语音日记素材 | 非核心 | 砍掉，工坊只保留录音+哼唱 |
| 画作配乐 | 实现复杂 | 砍掉，Demo 不做 |
| 情绪红绿灯预警 | 伦理复杂 | 砍掉，保留基础情感陪伴文案 |
| 语音评论 | 前端工作量大 | 只保留点赞（星星） |
| 成就徽章 | 非核心 | 砍掉 |
| 推荐算法 | 时间不够 | 按时间倒序 |
| 完整注册登录 | 非必要 | 设备码自动生成，一行代码 |
| 多端适配 | 时间不够 | 只做 375px 移动端竖屏 |
| 复杂解锁动画 | 时间不够 | 简单弹窗 + CSS 渐变 |
| 自由语音指令调整 | 技术风险 | 预设 3 个风格按钮 |

### MVP 最终范围（一句话）

> **3 个学院关卡 + 1 个工坊 AI 生成 + 4 只鸟图鉴 + 社区列表点赞，用 Web App 形态，评委扫码即用。**

### 2.3 数据结构

```typescript
interface Bird {
  id: number;
  name: string;           // "北长尾山雀"
  englishName: string;    // "Long-tailed Tit"
  category: 'cute' | 'abstract' | 'mystery';
  description: string;    // 解锁文案
  avatar: string;         // 图片 URL
  avatarGray: string;     // 灰色剪影 URL
  fragmentType: string;   // "绒羽" | "怪羽" | "暗羽"
  fragmentNeeded: number; // 需要多少碎片，0=初始鸟
  birdCall: string;       // 鸟叫音频 URL
}

interface UserFragment {
  userId: string;
  fragmentType: string;
  count: number;
}

interface BirdUnlock {
  userId: string;
  birdId: number;
  unlocked: boolean;
}
```

### 2.4 碎片获取规则

| 碎片类型 | 获取方式 | 数量 |
|---------|---------|------|
| 绒羽碎片 | 完成学院关卡 1 次 | +2 |
| 绒羽碎片 | 高分完成（全对） | +3（替代上面的 +2） |
| 怪羽碎片 | 在工坊完成 1 首作品并发布 | +3 |
| 暗羽碎片 | 在社区发布作品 | +2 |
| 暗羽碎片 | 作品被点赞 | +1（每日上限 3） |

**交互流程：**
1. 进入关卡 → 小鸟语音讲解（TTS 播放）→ 播放第 1 题的两个音
2. 两个音依次播放（间隔 0.5 秒），第一个音低沉，第二个音或高或低
3. 孩子点击「上楼」或「下楼」按钮
4. 答对：✅ 绿色反馈 + 叮咚音效 → 自动播放下一题
5. 答错：❌ 红色提示 + 「再听一次」按钮 → 可重试
6. 3 题答对 2 题即通关
7. 通关：弹出碎片获得弹窗 → 返回地图

**技术实现：**
- Tone.js 播放音频：使用 `Tone.Synth` 生成不同音高的音
- 音高对：如 C4 vs G4（低 vs 高），随机生成
- 判定：纯前端逻辑，无需后端

```
│      └─────────┘        │
│                         │
│  ● ● ● ○ ○ ○ ○ ○      │

├─────────────────────────┤

└─────────────────────────┘
```

**交互流程：**
1. 进入关卡 → 小鸟讲解 → 3-2-1 倒计时
2. 背景音乐开始播放（80BPM 稳定节拍）
3. 屏幕中央大鼓，孩子需要跟着节拍点击
4. 判定窗口：±200ms 内点击算「命中」
5. 命中：鼓面动画 + 鼓声音效
6. 未命中：鼓面不动 + 提示「快一点/慢一点」
7. 连续命中 6 拍即通关（总共 8 拍窗口，允许 2 次失误）
8. 通关：碎片获得弹窗

**技术实现：**
- Tone.js `Transport` 控制节拍时钟
- `Tone.Transport.scheduleRepeat()` 每拍触发
- 记录每次点击时间戳，与最近的节拍时间对比
- 判定窗口：|点击时间 - 节拍时间| < 200ms

1. 进入关卡 → 小鸟讲解 → 播放标准 Do 音
2. 屏幕显示「跟我唱！」+ 音高指示器
3. 孩子对着麦克风唱
4. 实时检测音高，显示在指示器上
5. 判定：检测到的音高与目标音高差 < 2 个半音 = 通过
6. Do 通过 → 自动播放 Re → 再唱 Re
7. Do Re Mi 三个音都通过 = 通关
8. 通关：碎片获得弹窗

- 判定容差：±2 半音（约 ±15% 频率差）
- 音高指示器：一个上下移动的圆点，实时反映当前音高

**技术实现（双轨方案）：**

```
方案 B（保底，优先实现）：
  1. 前端录制哼唱 → 上传到后端
  2. 后端 librosa 分析：提取调式(C/Am/G等) + 节拍(BPM)
  3. 根据调式 + 选择的风格，匹配预生成的伴奏模板
  4. 将哼唱音频 + 伴奏模板用 pydub 混音
  5. 返回混音后的音频 URL

方案 A（增强，有时间再做）：
  1. 同上 1-2 步
  2. 用 ACE-Step 根据旋律特征生成定制伴奏
  3. 混音输出
```
